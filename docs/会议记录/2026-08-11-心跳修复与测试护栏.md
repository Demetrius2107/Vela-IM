# 2026-08-11 心跳修复与测试护栏

## 一、背景

基于 glm5.2 对 Vela 项目的现状分析（含二次代码核验），确认 P0 缺陷：TCP 心跳检测完全失效
（pipeline 无 `IdleStateHandler`、`HeartBeatHandler` 退后台逻辑为 TODO）。本次在
`fix/tcp-heartbeat-and-test-harness` 分支上完成 P0 修复及测试护栏首批落地。

## 二、完成工作

### P0 心跳修复（完整 3 步）

1. **`LimServer.java`**：pipeline 最前补 `IdleStateHandler`（ALL_IDLE = heartBeatTime，至少 1s），
   产生空闲事件供 HeartBeatHandler 使用；新增 `close()` 方法释放 Boss/Worker 线程组。
2. **`HeartBeatHandler.java`**：ALL_IDLE 分支修掉 null 陷阱（从未 PING 的连接此前永不超时断开），
   落地退后台逻辑——超时即 `ctx.close()`，由 `channelInactive → offlineUserSession` 复用既有链路
   完成 Session/Redis 清理与 MQ 下线通知。
3. **`SessionSocketHolder.java`**：`offlineUserSession`/`removeUserSession` 的 Redis 操作加 try-catch
   （测试暴露 NPE），清理链路尽力而为——Redis 异常不阻断本地清理与下线通知。

### 测试护栏首批

- **`LimServerHeartbeatTest`**（3 例，纯 Netty 端到端，不依赖中间件）：
  空闲连接超时断开 / 持续 PING 保持活跃 / 停发 PING 超时断开。
- **`TcpApplicationContextLoadTest`**（1 例）：@MockBean 隔离 TcpServerRunner，
  Spring 上下文离线加载护栏。
- `vela-tcp/pom.xml` 新增 `spring-boot-starter-test`（test scope）。

### 文档与数据修正

- `README.md`：单元测试数量修正为实际值（原"123 个"失真）。
- `docs/Vela项目启动问题完整清单.md`：11.3 节标记已修复。

## 六、风险与说明

- 心跳语义：PING 为唯一活性依据（`READ_TIME` 仅 PING 分支刷新），业务消息不算活性——
  与客户端 `heartBeat.py` 每 10s PING 的约定一致。
- 端到端断连行为已由测试覆盖（离线可跑）；登录/消息链路的真实联调验证仍需中间件环境。
