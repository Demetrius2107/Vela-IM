### 护栏暴露并修复的启动缺陷（8 项）

1. **`LocalHashEmbedding` 类名误改**：`atLocalHashEmbedding` → 恢复 `LocalHashEmbedding`
   （public 类名必须与文件名一致，否则编译失败）。
2. **GroupApplication 缺 message 包扫描**：`GroupBroadcastNode`/`GroupMessageService` 构造器
   注入 message 模块 Bean（`MessageStoreService`/`RateLimitNode`/`DedupNode`），补
   scanBasePackages + @MapperScan。
3. **message/user 模块同名 `vela-group` FeignClient 重复注册**：跨模块扫描后两个
   `@SpringBootApplication` 配置类各自的 `@EnableFeignClients` 重复注册
   `vela-group.FeignClientSpecification` → group/admin 的 application.yml 补
   `allow-bean-definition-overriding: true`（与 message 模块既有做法一致）。
4. **group 孤儿 `ImGroupMessageHistoryMapper` 冲突**：与 common.entity 版同名 Mapper 无业务
   引用、无 XML 映射，经确认后删除（连同仅它引用的 group 版 `ImGroupMessageHistoryEntity`）。
5. **group 构造器循环依赖**：`ImGroupServiceImpl` ↔ `ImGroupMemberServiceImpl`（含自引用），
   加 `@Lazy` 打破。
6. **bot/office/config/admin 缺 `com.vela.im.shared` 扫描**：`CallbackService` 需要
   `HttpRequestUtils` Bean，四个 Application 的 scanBasePackages 补齐。
7. **AdminApplication 跨模块依赖不足**：`AdminService` 依赖 user/message/group/bot 的
   Mapper 与 Service，扩展 scanBasePackages + @MapperScan；测试补 `@MockBean FeatureFlagService`。
8. **ConfigApplicationContextLoadTest 误用 JUnit 4**：`org.junit.Test` → `org.junit.jupiter.api.Test`
   （JUnit 5 引擎不执行 JUnit 4 注解）。

## 六、风险与说明

- **allow-bean-definition-overriding: true** 是跨模块扫描下容忍同名 Bean 的既有模式
  （message 模块先例），非本次引入；代价是 Bean 覆盖静默，后续跨模块扫描需留意同名 FeignClient。
- 护栏测试为**离线上下文加载护栏**：验证 Bean 组装与启动期配置，不覆盖真实消息链路；
  真实联调仍需中间件环境。
- 删除的 group 版 `ImGroupMessageHistoryMapper/Entity` 无业务引用（git 可恢复），
  message 模块实际使用 common.entity 版，行为不受影响。
