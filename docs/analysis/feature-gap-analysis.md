# Vela IM 功能现状 vs 主流 IM 平台差距分析

> 版本: v1.0 | 创建时间: 2026-07-27
> 对比对象: 企业微信 · 飞书 · 钉钉 · Telegram

---

## 一、概述

Vela 当前处于 **IM 引擎内核**阶段，完成了消息收发、关系链、群组等基础能力。
但对比成熟 IM 产品，在**功能完整性**上差距仍然明显。

## 三、差距总览

### Vela 已实现（核心引擎层）

```
共约 20 项基础功能
```

主要集中为：消息收发、好友关系链、群组管理、会话管理、离线消息、多端同步

### Vela 未实现（按优先级）

#### 🟢 短期内可做（无外部依赖，纯后端逻辑）

| 功能 | 预估工时 | 说明 |
|------|--------|------|
| 消息引用回复 | 1-2 天 | 回复时携带原消息 ID + 摘要文本 |
| @提及 | 1 天 | 解析 @语法 + 存储 @关系 + 推送通知 |
| 消息转发（逐条） | 2 天 | 选择消息 → 选择目标 → 发送 |
| 合并转发 | 2-3 天 | 多条消息合并为一个转发卡片 |
| 群公告 | 2 天 | 公告 CRUD + 已读统计 |
| 群@所有人 | 0.5 天 | 特殊逻辑：仅管理员/群主可触发 |

#### 🟡 中期可做（需前端配合，但后端改动不大）

| 功能 | 预估工时 | 说明 |
|------|--------|------|
| 群二维码/邀请链接 | 2 天 | 生成短链接 + 扫码入群 |
| 消息收藏 | 2 天 | 收藏 CRUD + 跨端同步 |
| 联系人备注/标签 | 1 天 | 备注名、标签分组 |
| 消息搜索 | 3-5 天 | 基于 Elasticsearch 全文检索 |

#### 🔴 远期（需要大量资源）

| 功能 | 说明 |
|------|------|
| 文件/图片/视频消息 | 需文件存储服务（OSS/MinIO）|
| 语音消息 | 需音频编解码 + 存储 |
| 音视频通话 | 需 WebRTC + SFU 服务 |
| 客户端（Win/Mac/Android/iOS）| 需原生开发资源 |
| 端到端加密 | 需协议层重设计 |

## 四、对比结论

1. **Vela 当前 ≈ 2013 年的微信** — 功能极度精简，只有核心 IM 内核
2. **与企微/飞书/钉钉的差距主要在"办公协作生态"** — 这些是 IM + OA 一体化，Vela 的目标不应是追上这个
3. **与 Telegram 的差距主要在"协议层能力"** — E2E 加密、Bot 平台、Channel
4. **Vela 当前最适合对标的是"开源 IM 引擎"（如 OpenIM）** — 专注消息收发和关系链，不做大而全

### 建议

如果目标是**把 Vela 做成一个真正能用的 IM**，接下来最值得做的不是性能优化，而是：

```
1️⃣  消息引用回复      ← 群聊体验的关键
2️⃣  消息转发           ← 信息分发的基本能力
3️⃣  @提及              ← 群聊协作的基本能力
4️⃣  群公告             ← 群管理的必需功能
5️⃣  图片/文件消息       ← 不是纯文本的 IM
```

这些加起来大约 **1-2 周** 的开发量，完成后 Vela 就从"消息引擎"变成了"能用（虽然简陋）的 IM"。
